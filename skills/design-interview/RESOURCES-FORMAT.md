# RESOURCES.md 格式

`RESOURCES.md` 在面试工作区根，位置按 `SKILL.md` 的「工作区选择」确定，不一定是调用目录。它是这份面试工作区的高信任资料清单。技术事实从这里来。设计一轮之前，若目标能力在清单里还没有来源，先检索、打开页面、把条目写上，再出技术事实题。检索失败写缺口，可改成只问无争议简历锚点上的经历。

## 检索什么

按本轮需要，优先找这些能点开的页面：

1. 该公司该岗位的官方招聘说明、级别说明
2. 该公司工程博客、工程手册、他们署名发表的实践文
3. 该能力的官方文档、RFC、标准或论文
4. 用户指出的本人仓库、演讲或文章

把实际打开并决定采用的 URL 写入 `RESOURCES.md`。等待必要确认且未能落盘时，至少列在回复的「已完成」清单。检索失败或打不开页面时，不要用记忆填条目或技术事实；在「缺口」里写缺什么。

**检索停止线：** 本轮目标能力已经有采用的来源，或已经决定改问经历，就进入设计，不再为低增量页面继续检索。

## 模板

```md
# 资料

## 岗位
- [招聘页：{角色名}]({url})
  {一句话：覆盖哪几条 JD 要点，出哪类题时打开它。}
- [参考岗位画像：{公开岗位角色名}]({url})
  参考岗位画像 · 不是目标公司实际要求。{一句话：哪项目标能力可用它作参考。}

## 一手技术
- [文档：{标题}]({url})
  {一句话：哪项目标能力以它为准。}

## 工程文化
- [工程博客：{标题}]({url})
  {一句话：它约束哪种取舍或上线标准。}

## 候选人产物
- [仓库或演讲：{标题}]({url 或本地路径})
  {一句话：对应 RESUME 的哪一段。}

## 缺口
- {MISSION 里某条要点还没有高信任源，或完整 JD 未提供。若本轮改问经历，在这里记明。}
```

没有内容的分组可以省略。「缺口」在确实有缺口时保留；没有缺口就不要写空标题。

## 英文标题

`# Sources` · `## Job` · `## Primary technical` · `## Engineering culture` · `## Candidate artifacts` · `## Gaps`

## 规则

- **高信任才收。** 官方招聘页、公司自己的工程写作、官方文档、标准、论文、用户给出的本人材料。
- **每条都有注解。** 写它覆盖什么、什么时候打开。三个月后只有一个裸链接等于没有。
- **一条来源对应得上岗位或简历。** 对不上当前 `MISSION.md` 的资料不收。
- **参考岗位画像仍是高信任来源。** 公司未知时，可采用打开过的官方公开岗位说明，但条目标题标「参考岗位画像」，注解写明「不是目标公司实际要求」。`MISSION.md` 摘出的要点带同一标签，不把另一家公司或级别移作目标要求。
- **匿名面经和榜单体题单不收。** 职场论坛上的「面经」、"Top N interview questions"、转载且没有出处的清单，都不能当出题依据。用户明确要求参考市场传闻时，单独标成传闻，并且仍然不能只凭它出题。
- **不设社区分组。** 本技能不把论坛、社群经营写成资料类别。
- **写缺口。** 某条 JD 要点没有好来源时，写进「缺口」，不以填满清单为本轮完成条件，不用记忆补题。已决定改问经历就停止本轮检索。
- **删掉后来发现是错的或浅的条目。** 留下少量能用的，比堆三十条强。
- **本地材料写用户给的路径。** 用户给的 PDF 或简历文件注明是用户提供的，不猜私人路径。面试工作区内的产物路径相对面试工作区根；Markdown 链接目标相对本文件所在目录。
