# RESUME.md 格式

`RESUME.md` 在工作区根目录。它是候选人简历的结构化摘要。设计题目时对照它选简历锚点。只记录用户说过的话，或用户指定文件里写明的内容。

## 模板

```md
# 简历摘要

## 身份
- 姓名或称呼: {用户希望在面试稿里使用的称呼；用户没给就写「候选人」}
- 目标岗位: {与 MISSION 一致}

## 项目
### {项目名}
- 是什么:
- 为何做:
- 个人贡献:
- 数据: {只写原文里的数字。没有就写「原文无数字」}
- 栈:

## 技术栈
- {用户列出的，分组即可}

## 缺口
- {JD 要点里简历没写到的}
- {用户说自己不深的地方}

## 不确定
- {摘要时拿不准、需要用户确认的句子}
```

## 英文标题

`# Resume` · `## Identity` · `## Projects` · `## Stack` · `## Gaps` · `## Uncertain`

项目内字段：`What` / `Why` / `Own contribution` / `Metrics` / `Stack`。

## 规则

- **不编指标。** 简历没写的百分比、延迟、人数，一律不补。
- **缺口是加压的边界。** 缺口处可以出「JD 要求、简历没写」的加压题，但不得描述成候选人的既有项目。
- **个人贡献写清「谁做的」。** 「我们」无法分辨时放进「不确定」，开场不要拿它当深挖点。
- **一份摘要，不是简历全文重排。** 长简历收成能出锚点的项目和数字。
- **用户改口就改文件。** 被替换的数字不要留两套。

## 格式示例

下面是字段形状，不是某位候选人的简历，不要拿去当锚点。

```md
### 内部知识库助手
- 是什么: 检索、重排、带引用的回答串成一条可评测链路
- 为何做: 支持同事少翻文档
- 个人贡献: 评测集与上线门禁
- 数据: 原文无数字
- 栈: 以用户简历为准
```
