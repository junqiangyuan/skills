# RESUME.md 格式

`RESUME.md` 在面试工作区根，位置按 `SKILL.md` 的「工作区选择」确定，不一定是调用目录。它是候选人简历的结构化摘要。设计题目时对照它选简历锚点。只记录用户说过的话，或用户指定材料里写明的内容；多版本未确认时只整理一致的内容。

## 模板

```md
# 简历摘要

## 来源
- Resume source: {用户指定路径或「用户粘贴」；多版本未指定时列出用户提供的版本位置，标「待确认」，不自行选权威版本}
- 确认状态: {已确认（用户已指定来源） | 待确认（仅用一致内容） | 未提供（用户明确只按 JD 筛查）}

## 身份
- 姓名或称呼: {用户希望在面试稿里使用的称呼；用户没给就写「候选人」}
- 目标岗位: {与 MISSION 一致}

## 项目
### {项目名}
- 是什么:
- 为何做:
- 个人贡献:
- 数据: {只写原文里的数字。没有就写「原文无数字」}
- 栈:

## 技术栈
- {用户列出的，分组即可}

## 缺口
- {JD 要点里简历没写到的}
- {用户说自己不深的地方}

## 不确定
- {摘要时拿不准、需要用户确认的句子}
- {多版本冲突：项目名 / 职责 / 日期 / 指标的差异及各自来源；是否影响本轮锚点}
```

## 英文标题

`# Resume` · `## Source` · `## Identity` · `## Projects` · `## Stack` · `## Gaps` · `## Uncertain`

来源字段：`Resume source` / `Confirmation status`。状态职责不变。

项目内字段：`What` / `Why` / `Own contribution` / `Metrics` / `Stack`。

## 规则

- **记录来源指针。** `Resume source` 写用户指定路径或粘贴，并记录确认状态。工作区内的材料路径相对面试工作区根；外部路径照用户提供的记，不猜私人路径。
- **多版本只问影响本轮的差异。** 比较项目名、职责、日期、指标。用户已指定权威版本就用该版本；未指定时，只询问会改变本轮锚点的差异，不为无关差异暂停准备。
- **一致内容先写。** 各版本一致的内容可先写入摘要，成为无争议锚点。冲突事实只在「不确定」，不进项目贡献、数据、题面或口语参考答。只暂停依赖冲突的题，无争议锚点上的经历题可以先写。
- **不拼接连续经历。** 不把多个版本拼成一段连续经历，也不拼职责或指标来补完整项目。
- **确认后沿用指针。** 权威版本确认后更新来源及确认状态，后续轮次沿用，不每轮重问。
- **不编指标。** 简历没写的百分比、延迟、人数，一律不补。
- **缺口是加压的边界。** 缺口处可以出「JD 要求、简历没写」的加压题，但不得描述成候选人的既有项目。
- **个人贡献写清「谁做的」。** 「我们」无法分辨时放进「不确定」，开场不要拿它当深挖点。
- **一份摘要，不是简历全文重排。** 长简历收成能出锚点的项目和数字。
- **用户改口就改文件。** 被替换的数字不要留两套。

## 格式示例

下面是字段形状，不是某位候选人的简历，不要拿去当锚点。

```md
### 内部知识库助手
- 是什么: 检索、重排、带引用的回答串成一条可评测链路
- 为何做: 支持同事少翻文档
- 个人贡献: 评测集与上线门禁
- 数据: 原文无数字
- 栈: 以用户简历为准
```
